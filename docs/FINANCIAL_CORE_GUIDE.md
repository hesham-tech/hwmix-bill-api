# دليل النواة المالية والمحاسبية المحدثة (Financial Core Guide)

---

## 📌 مقدمة
يوضح هذا المستند التقني المعمارية المالية والمحاسبية المحدثة لنظام **HWNix ERP** متعدد الشركات (Multi-Tenant SaaS). يهدف التصميم الجديد إلى تحقيق الفصل التام بين الأرصدة النقدية (الخزائن والبنوك) والأرصدة الدفترية (مديونيات العملاء والتزامات الموردين).

---

## 🏦 1. مصادر الحقيقة للأرصدة (Sources of Truth)

### 1.1 رصيد الخزنة (CashBox Balance)
* **المصدر الرسمي:** مجموع المعاملات الحركية الفعالة في جدول `transactions` المرتبطة بـ `cashbox_id` المحدد.
* **الرصيد المخزن (`cash_boxes.balance`):** عبارة عن لقطة سريعة (Cached Snapshot) يتم تحديثها فوراً وتلقائياً عبر الحركات المالية لضمان الأداء السريع، ويجب أن يطابق مجموع الحركات بالقرش.

### 1.2 رصيد الطرف (Stakeholder Balance)
* **المصدر الرسمي:** السجل التراكمي في جدول **`stakeholder_financial_balances`** المصفى بالشركة `company_id` ونوع العلاقة `relation_type` (عميل مدينة `receivable` / مورد دائنة `payable`).
* **تكامل الذمم:** يتم رصد ومطابقة رصيد الطرف بالقرش عبر جمع حركات قيود المعاملات المرتبطة به.

---

## 🔁 2. قواعد تسجيل المعاملات المالية (Transactions Rules)

تخضع جميع الحركات المالية لقاعدة تسجيل الأثر المزدوج والتدقيق الكامل:

| نوع العملية | أثر الخزنة (`cashbox_id`) | أثر رصيد الطرف (`stakeholder_financial_balances`) | نوع القيد في `transactions` |
| :--- | :--- | :--- | :--- |
| **إنشاء فاتورة بيع (أجل)** | لا يوجد (`null`) | زيادة المدين (+ `net_amount`) | قيد إيداع دفتري (`deposit`) |
| **سداد فاتورة بيع (نقداً)** | سحب/إيداع بالخزنة (`$staffBox->id`) | تخفيض المدين (- `paid_amount`) | قيد إيداع نقدي (`deposit`) |
| **إلغاء فاتورة بيع** | لا يوجد (`null`) | تخفيض المدين (- `net_amount`) | قيد سحب دفتري (`withdraw`) |
| **إنشاء فاتورة شراء (أجل)** | لا يوجد (`null`) | زيادة الدائن (+ `net_amount`) | قيد سحب دفتري (`withdraw`) |
| **سداد فاتورة شراء (نقداً)** | خصم من الخزنة (`$staffBox->id`) | تخفيض الدائن (- `paid_amount`) | قيد سحب نقدي (`withdraw`) |

## 👥 3. طبقة التوافقية للخلف (Legacy Compatibility Layer)

للحفاظ على استقرار الكود التاريخي والـ APIs والتقارير التي تستعلم عن رصيد المستخدمين مباشرة عبر خاصية `$user->balance`، تم تزويد نموذج `User` بـ Accessor ذكي يعمل كالتالي:

```php
    public function getBalanceAttribute()
    {
        $companyId = $this->active_company_id ?? $this->company_id ?? null;
        if ($companyId) {
            $financialBalance = \Modules\Companies\Models\StakeholderFinancialBalance::where([
                'company_id' => $companyId,
                'user_id' => $this->id,
            ])->first();

            if ($financialBalance) {
                return (float)$financialBalance->balance;
            }
        }
        return $this->active_branch_balance;
    }
```
* **تنبيه للمستقبل:** يجب استبدال التخاطب مع `$user->balance` بالخصائص الصريحة:
  * `cashbox_balance`: للحركات النقدية الفعلية.
  * `financial_balance`: للذمم والمديونيات الدفترية للأطراف.

## 🧪 4. أمثلة لتدفق العمليات المالية (E2E Flows)

### 4.1 دورة بيع آجل وسداد
1. **إنشاء فاتورة بيع بقيمة 3000 وقبض 1000:**
   * يتم استدعاء `AccountingService::recordInvoiceCreation`.
   * ينشأ قيد دفتري بـ 3000 ليزداد رصيد العميل التراكمي إلى `+3000`.
   * ينشأ قيد دفع نقدي بـ 1000 لتزداد خزنة الفرع بـ `+1000` وينخفض رصيد العميل التراكمي إلى `+2000`.
2. **إلغاء الفاتورة بالكامل:**
   * يتم استدعاء `AccountingService::reverseInvoice`.
   * يتم خصم الـ 3000 بالكامل من رصيد العميل ليعود رصيد ذمته إلى `-1000` (أي يطالبنا بـ 1000).
   * يتم استرداد الـ 1000 نقداً من الخزنة ليعود رصيد الصندوق لوضعه الأصلي.

## 🛡️ 5. أداة الفحص والتدقيق التلقائي (Financial Health Check)

يوفر النظام أمر Artisan متقدم للمراجعة التلقائية للسلامة العامة للحسابات وكشف الحيود:
```bash
php artisan financial:audit-balances
```

### الفحوصات الجارية:
1. مطابقة أرصدة كافة الصناديق الفردية والمشتركة مع صافي الحركات التابعة لها.
2. مطابقة أرصدة الذمم والمديونيات للأطراف مع صافي قيود المعاملات الدفترية والنقدية الخاصة بهم.
3. كشف المعاملات اليتيمة (المعلقة بمستخدمين أو خزائن محذوفة).
4. كشف الفواتير المعلقة بحسابات وهمية.
5. رصد الحركات يتيمة المصدر (بدون فواتير مرجعية منطقية).
