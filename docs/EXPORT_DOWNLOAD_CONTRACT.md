# تنزيل ملفات تصدير المنتجات

يبقى المسار `GET /api/v1/export-import/download/{id}` كما هو، ويحتاج `Authorization: Bearer …` عبر Sanctum. قيمة `download_url` في مورد المهمة عنوان API، وليست رابط مشاركة عامًّا أو موقعًا لوضع التوكن في query string.

تحديث نطاق الفرع: جدولة التصدير تلتقط شركة الحساب وفرعًا واحدًا مفوضًا من X-Branch-Id/السياق المعتمد، أو فرع الموظف الافتراضي/أول فرع مسموح الموافق للقراءة عند غياب الاختيار. مدير بلا اختيار يلزمه تحديد فرع. `all` أو فرع غير صالح422، وفرع أجنبي أو غير مسند403. لا fallback إلى كل الشركة. العامل يستخدم اللقطة المخزنة ويتحقق من ملكية الفرع للشركة، ويسمي كل ملف بمعرف المهمة وUUID لمنع تصادم ملفات الفروع. تبديل الفرع بعد الجدولة لا يغير المحتوى.

المهام القديمة branch-null لا يُعاد إسناد فرع لها ولا يعرض المورد رابطها؛ التنزيل404 والعامل لا يولد لها ملفًا جديدًا دون نطاق مثبت. أعد الجدولة من الفرع الصحيح. لا حذف ملفات تاريخية أو migration أو إعادة توليد جماعية ضمن هذا التغيير.

- شركة التنزيل هي `active_company_id` للمستخدم الموثق، مع عضوية active أو صلاحية admin.super. تغيير هيدر الشركة لا ينقل التنزيل لشركة أخرى؛ يجب أولًا تبديل الشركة النشطة بالآلية المعتمدة.
- يُحافظ على نطاق الفرع والحذف الناعم. الطلب خارج الشركة/الفرع أو لمهمة محذوفة/استيراد يرجع404. المستخدم دون سياق شركة أو عضوية صالحة يرجع404.
- تنزيل products يتطلب products.export أو admin.super داخل الشركة المحددة. الأنواع التي ليس لها exporter وصلاحية محددة لا تُتاح للتنزيل، حتى للمشرف؛ ترجع403. لا يضيف هذا التغيير دعم تصدير invoices/customers.
- الضيف يرجع401؛ غياب صلاحية النوع يرجع403؛ المهمة غير المكتملة أو الملف المفقود يرجع404. أخطاء HTTP لا تتحول عمدًا إلى500 تحتوي رسالة استثناء.
- النجاح200 مع ملف CSV باسم `products_export_{id}.csv` وCache-Control:private,no-store. لا تغيير مخطط أو تنسيق CSV أو إنشاء ملفات جديدة ضمن طلب التنزيل.

الواجهة تستخدم عميل Axios المشترك لتضمين سياق المصادقة، وتبني المسار النسبي من job ID ثم تحفظ Blob، بدل فتح download_url مباشرة أو إرسال التوكن لعنوان من الاستجابة. جدولة التصدير تبقى `POST /api/v1/export-import/export` والمتابعة `GET /api/v1/export-import/{id}`.

## التوافق والإطلاق

حدّث عميل التنزيل قبل تشديد الباك إند على بيئة مستخدمة. العميل الجديد يظل يرسل طلب GET قياسيًا إلى المسار نفسه. يجب تحديث أي عميل موبايل أو تكامل خارجي كان يفتح الرابط دون Authorization؛ لا يُستبدل ذلك بتوكن في URL أو استثناء للضيف.

عند فشل الإطلاق، أبق التنزيل مغلقًا مؤقتًا وأصلح العميل/الاعتماد؛ لا تتراجع إلى تنزيل دون مصادقة. لا DB rollback مطلوب. هذا التغيير يحمي مسار API المحدد؛ نقل ملفات public disk إلى تخزين خاص وتنظيف الروابط القديمة عمل منفصل في خطة التدقيق.

المراجع: [حماية مسارات Sanctum](https://laravel.com/docs/12.x/sanctum#protecting-routes)، [تنزيل الملفات](https://laravel.com/docs/12.x/filesystem#file-downloads).

## نطاق بيانات المنتجات

كتالوج المنتجات مشترك داخل الشركة كما في قائمة المنتجات الحالية؛ جدول products لا يحتوي branch_id. ملف CSV يصدر كتالوج الشركة ولا يتضمن أرصدة أو أسعار مخازن الفروع. branch_id المحفوظ يحدد سياق إنشاء المهمة وصلاحية متابعة ملفها وتنزيله، ولا يعني ملكية صفوف المنتجات لفرع. لا تُضاف أعمدة أو توزيع منتجات جديد؛ تصدير مخزون فرع يحتاج عقدًا منفصلًا. يظل كتالوج الشركات الأخرى مستبعدًا.
