# صلاحيات نسخ النظام وتأكيد الهوية

جميع عمليات `/api/v1/backups`، بما فيها القائمة والإعدادات والتشغيل والتنزيل والحذف والاستعادة، تتطلب Sanctum وصلاحية `admin.super`. نسخ النظام قد تضم كل الشركات؛ صلاحيات `admin.company` أو `backups.*` لا تمنح الوصول، ولا تُرشح النسخة الشاملة باسم الشركة النشطة. الضيف401 وغير مدير النظام403 قبل بيانات النسخ أو التخزين أو الخدمة.

## تأكيد التنزيل والاستعادة

1. يرسل المدير `POST /api/v1/backups/confirm-password` مع `password` و`action` (`download` أو`restore`) و`backup_id` موجب.
2. عند صحة كلمة مرور الحساب تعاد `data.confirmation_token` و`expires_in:300`. المحاولة محدودة بخمس مرات في الدقيقة، بما فيها الفاشلة. كلمة المرور الخاطئة422، والتجاوز429.
3. يرسل المدير التأكيد في هيدر `X-Backup-Confirmation-Token` على طلب التنزيل أو الاستعادة. يرتبط التأكيد بهوية المدير وتوكن Bearer/الجلسة والغرض ومعرف النسخة؛ ينتهي خلال خمس دقائق. يعاد تقييم admin.super في كل طلب. ليس رابط مشاركة ولا يوضع في query string أو التخزين المحلي، وليس تأكيدًا أحادي الاستخدام.
4. الاستعادة تحتاج كذلك `token`، رمز الاستعادة الإضافي السابق، في جسم الطلب. لا تعرضه واجهة الإعدادات ولا يمكن تغييره عبرها. يُدار عبر قناة تشغيل آمنة؛ لا تطبعه في التذاكر أو المحادثات. المعرفة القديمة بهذا الرمز وحدها لا تتجاوز الصلاحية وكلمة المرور الحالية.

غياب التأكيد أو عدم مطابقته أو انتهاؤه403. نسخة مفقودة أو غير ناجحة404، دون مسار قرص أو تفاصيل استثناء. التنزيل200 مع ملف zip وprivate,no-store. لا يُشغّل اختبار استعادة أو نسخة حقيقية لمجرد التحقق من هذا العقد.

## الإعدادات والمخرجات

GET settings يعيد أربعة إعدادات فقط بنفس شكل مصفوفة key/value/type. PUT يسمح بتحديث جزئي لهذه المفاتيح، ويرفض أي مفتاح آخر أو قيمة غير صالحة422 دون تطبيق جزء من الطلب:

- `backup_frequency`: daily/weekly/monthly/none.
- `backup_time`: HH:mm.
- `backup_retention_days`: عدد صحيح من1 إلى365.
- `backup_include_files`: boolean JSON أو0/1.

لا تُعاد أسرار الإعدادات أو disk/error_message في التاريخ، ولا خرج أوامر النسخ في رد التشغيل. سجل العمليات يحتوي معرف المستخدم والفعل ومعرف النسخة والنتيجة فقط؛ لا كلمة مرور أو تأكيد أو رمز استعادة أو command/output.

## التوافق والحدود

الواجهة الجديدة تطلب كلمة المرور للتنزيل والاستعادة وتحذفها من النموذج بعد المحاولة. يبقى رمز الاستعادة حقلًا مستقلًا. العملاء القدامى لا يستطيعون تنزيل/استعادة النسخة دون تنفيذ التأكيد الجديد. يُفضل نشر الباك إند المقيد أولًا ثم الواجهة؛ يفشل العميل القديم مغلقًا خلال نافذة التحديث. يدعم CORS الهيدر المحدد دون توسيع قائمة الأصول أو تفعيل cookies.

هذا الإصلاح تفويض وعقد عميل، وليس اعتمادًا لسلامة محرك الاستعادة أو RPO/RTO أو اختبارًا لاستعادة إنتاج. مهام معالجة أوامر الاستعادة والنسخ المتزامن وخطة التعافي تبقى مستقلة. التراجع يبقي HTTP محميًا أو يوقف العملية503 مؤقتًا، ولا يعيد وصول مستخدم عادي أو عرض الأسرار.

مراجع: [سياسات Laravel](https://laravel.com/docs/12.x/authorization#creating-policies)، [تأكيد كلمة المرور](https://laravel.com/docs/12.x/authentication#password-confirmation)، [تشفير Laravel](https://laravel.com/docs/12.x/encryption). التأكيد هنا خاص بعملاء API المرتبطين بـBearer؛ لا يعتمد على جلسة password.confirm في المتصفح.
