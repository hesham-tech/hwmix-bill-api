# فلاتر كتالوج المتجر

يدعم GET /api/v1/store/public/products التحديد المتعدد عبر category_ids[] وbrand_ids[]، إضافة إلى البحث والسعر والمخزون والترتيب والترقيم الموجودة مسبقًا.

مثال: category_ids[]=7&category_ids[]=8&brand_ids[]=20&brand_ids[]=21.

- داخل قائمة التصنيفات تُقبل المنتجات التابعة لأي تصنيف محدد (OR)، وداخل البراندات كذلك. يُجمع النوعان معًا بالشروط الأخرى (AND).
- كل قائمة تحتوي حتى24 معرّفًا موجبًا غير مكرر؛ المدخلات غير الصالحة تعيد422 دون تنفيذ استعلام الكتالوج.
- category_id وbrand_id القديمان ما زالا مدعومين. إذا أرسل العميل قائمة غير فارغة ومعرّفًا مفردًا لنفس النوع، تُستخدم القائمة. القائمة الفارغة لا تضيف شرطًا، مع بقاء fallback للمعرّف المفرد إن أُرسل.
- لا تغيير للاستجابة أو حدود الترقيم أو أهلية الشركة للنشر أو قواعد إتاحة المخزون والأسعار. لا migrations أو تعديل بيانات ضمن هذا التغيير.

اختبارات StoreCatalogFiltersTest تستخدم اتصال SQLite في الذاكرة صراحة دون تحميل Laravel أو .env أو migrations؛ تتحقق من نتائج AND/OR والتوافق القديم وحدود التحقق. لا تعتبر دليل أداء لمحرك الإنتاج. يضاف فحص HTTP على staging بعد النشر للتأكد من عمل التحقق والفلترة مع بيانات الاختبار وMySQL الفعلي.

ترتيب الرفع: الباك إند إلى staging أولًا، ثم الفرونت. رجوع التطبيق ممكن بإصدار الكود السابق دون تراجع قاعدة؛ إذا أعيد الباك إند القديم فيجب إعادة الفرونت القديم أيضًا لأنه لا يفهم القوائم الجديدة. لم يعدل workflow الإنتاج أو فرع master.
