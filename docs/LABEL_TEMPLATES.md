# قوالب ملصقات المنتجات

## الاستخدام

- الشاشة: `/app/label-templates` تحت **المنتجات والمخازن ← قوالب الملصقات**.
- أنشئ قالبًا، حدّد مقاس الملصق، وأضف النصوص والحقول والباركود وQR والصور والأشكال.
- اسحب العناصر أو عدّل إحداثياتها وأبعادها بالملليمتر. تتوفر الطبقات والقفل والتجميع والمحاذاة والتوزيع والتراجع والإعادة.
- يحفظ المحرر التعديلات تلقائيًا كمسودة بعد الحفظ الأول. انشرها بعد المعاينة لتصبح متاحة للطباعة.
- استخدم **تعيين افتراضي** لاختيار قالب الشركة. الاختيار داخل طلب طباعة لا يغيّر هذا الافتراضي.
- يمكن استعادة إصدار منشور سابق إلى مسودة. لا تتغير النسخة المنشورة إلا بالنشر الصريح.
- أرشفة الافتراضي تتطلب اختيار بديل منشور. النسخ ينشئ مسودة مستقلة.

أزرار الطباعة متاحة في قائمة المنتجات وتفاصيل المنتج وقائمة المتغيرات وبنود الفاتورة. توجد طباعة جماعية للمحدد في قائمتي المنتجات والمتغيرات. تستخدم جميعها النافذة والمحرك نفسيهما.

سعر الملصق الافتراضي هو **سعر البيع الحالي للمنتج** حتى عند الطباعة من فاتورة. سعر بند الفاتورة حقل مستقل للقوالب التي تحتاجه. تحدد الوحدة المختارة قيم حقول الوحدة وسعرها.

## الورق والجودة

- المقاسات محفوظة بوحدات فعلية. التكبير داخل المحرر لا يغيّر مقاس الطباعة.
- الرول: يعرض النظام مساحة الرأس الفعلية، ويرفض العناصر التي تقع خارجها بدل تصغير التصميم تلقائيًا.
- A4: صفوف وأعمدة، أربعة هوامش، فواصل، اتجاه الورقة، ترتيب الخانات من اليسار أو اليمين، وخانة البداية لتجاوز الملصقات المستخدمة.
- A4 تُطبع من المتصفح أو PDF. لا ترسل إلى مسار طابعة P2. استخدم حجمًا فعليًا 100% دون ملاءمة أو ترويسات.
- الباركود وQR يعاد توليدهما بمضاعفات نقاط صحيحة ومساحات أمان، ويُرفض الرمز الضيق أو ناقص البيانات.
- النص الزائد يتقلص ضمن الحد المحدد أو يُختصر بعلامة (…)؛ ارتفاع النص غير الكافي يُعرض كخطأ.
- Tahoma هو خط القالب القياسي على Windows. Noto Sans Arabic مضمن ومرخّص للتصميم المتوافق بين الأجهزة. الخط غير المتاح لا يُستبدل بصمت.
- صور القوالب: PNG/JPEG/WebP حتى 5 ميجابايت وبحد أبعاد 2048×2048، محفوظة في تخزين خاص بالشركة.

إعدادات برنامج P2 لم تتغير: **96 بايت / 20 مللي ثانية، سواد 3، انتظار 12 ثانية قبل فصل الاتصال**. المشروع يرسل PDF إلى الربط الحالي. لا يتطلب المحرر إصدارًا جديدًا من برنامج الطباعة؛ يُستخدم إصدار 1.1.4 المعتمد.

## البنية والصلاحيات

- الفرونت: `src/modules/print/templates-editor` للمخطط والمحرك والخدمة ولوحة Konva، و`pages` للمكتبة والمحرر، و`components` للمعاينة ونافذة الطباعة.
- الباك إند: قوالب وإصدارات داخل موديول Inventory. يحتوي JSON على وصف التصميم فقط، مع `schemaVersion: 1`، ولا يحفظ بيانات المنتج أو كائنات Konva.
- `products.print_labels`: قراءة المنشور وتجهيز بيانات الطباعة.
- `label_templates.manage`: إنشاء القوالب وإدارة المسودات والنسخ والاستعادة والأرشفة.
- `label_templates.publish`: النشر.
- `label_templates.set_default`: تعيين الافتراضي أو استبداله عند الأرشفة.
- المديرون يستخدمون تجاوز الصلاحيات الحالي، ويمكن تفويض الصلاحيات الجديدة عبر الأدوار.
- البيانات مقيدة بالشركة النشطة صراحةً، بما يشمل إدارة المنصة. لا يقبل الطلب شركة من جسمه لتحديد الملكية.
- أسعار الشراء والجملة تخضع لصلاحياتها الحالية. لا توجد تعبيرات JavaScript أو صيغ حسابية أو بيانات تسليم سرية في كتالوج الحقول.
- صور القوالب المرفوعة تستخدم القرص `local` الخاص تحت `label-template-assets/{company}`؛ تحميلها يتطلب صلاحية الشركة. لا تظهر في مكتبة الوسائط العامة، ولا تحذف إذا ارتبطت بإصدار محفوظ.
- اختيار القالب وإصداره وبيانات الطلب يثبت عند تجهيز المهمة. تنقية إعدادات الجهاز تمنع حفظ القوالب أو بيانات المنتجات في localStorage.

## الواجهات

تحت `/api/v1` ومع مصادقة Sanctum وسياق الشركة:

| الواجهة | الغرض |
| --- | --- |
| `GET /label-templates?published_only=1` | القوالب المنشورة والافتراضي |
| `GET /label-templates/fields` | الحقول والخطوط والصلاحيات وحالة تفعيل المحرر |
| `GET /label-templates/products` | بحث أو تحميل جماعي بوسيط `ids[]` أو `variant_ids[]`؛ بيانات اختيار قليلة دون أسعار |
| `POST /label-templates` | إنشاء مسودة |
| `GET /label-templates/{id}` | تفاصيل القالب والإصدارات المسموح بها |
| `PUT /label-templates/{id}` | حفظ المسودة مع `lock_version` |
| `POST /label-templates/{id}/publish` | نشر المسودة مع `lock_version` |
| `POST /label-templates/{id}/duplicate` | نسخة كمسودة مستقلة |
| `POST /label-templates/{id}/restore` | استعادة `revision_id` مع `lock_version` |
| `PATCH /label-templates/{id}/default` | تعيين الافتراضي |
| `DELETE /label-templates/{id}` | أرشفة مع `lock_version` و`replacement_id` إن كان افتراضيًا |
| `POST /label-templates/assets` | رفع صورة خاصة |
| `GET /label-templates/assets/{id}` | تحميل صورة مصرح بها |
| `POST /label-print-data` | نسخة منشورة محددة و`items` بمعرّفات المتغير/بند الفاتورة والوحدة والعدد |
| `POST /label-template-preview-data` | بيانات معاينة للمصمم دون نشر التصميم |

تعارض الحفظ يعيد HTTP 409 ويحافظ على التعديلات المحلية؛ يتيح المحرر تنزيل نسخة استرداد قبل إعادة التحميل. لا تتكرر الطباعة تلقائيًا عند الفشل.

## النشر والتحقق

نُفذت الترحيلات الثلاثة محليًا. عند نشر الباك إند السحابي، شغّل ترحيلات الميزة فقط بعد نشر مصادرها:

```sh
php artisan migrate --path=database/migrations/2026_10_28_120000_create_label_templates.php --path=database/migrations/2026_10_28_120100_seed_company_label_templates.php --path=database/migrations/2026_10_28_120200_add_label_template_permissions.php
```

تُنشأ القوالب القياسية للشركات الموجودة دون استبدال قوالبها، وللشركات الجديدة عبر CompanyObserver. لا تستخدم `migrate:fresh` على بيانات حقيقية.

للتفعيل التدريجي، `LABEL_TEMPLATES_ENABLED=true`، ويمكن حصر المحرر باستخدام `LABEL_TEMPLATES_COMPANIES=1,2`. القائمة الفارغة تفعّله للجميع. تعطيل المحرر يمنع إدارته ونشره، وتظل الطباعة بالإصدارات المنشورة تعمل؛ لا يُستبدل القالب المختار بقالب آخر عند الخطأ.

التحقق:

```sh
# في الفرونت
npm run test -- tests/unit/print
npm run test:printer
npm run build

# واجهة معزولة: شغّل الأول في طرفية، والثاني في أخرى
node tools/label-templates/qa-server.mjs
node tools/label-templates/verify-ui.mjs

# في الباك إند؛ phpunit.xml يستخدم SQLite في الذاكرة
php vendor/phpunit/phpunit/phpunit tests/Feature/LabelTemplateTest.php
```

فحص الواجهة يحاكي API ويحظر الوصول إلى خدمة الطباعة الفعلية، ويختبر الحفظ والنشر والافتراضي والتعارض وA4 وتبديل الشركة وقراءة الباركود وQR والخط المضمن. مخرجاته تحت `tools/label-templates/.qa-output`.

التحقق الورقي مؤجل بطلب المستخدم: يبدأ بملصق واحد من الموقع، ثم يُفحص المقاس والوضوح والباركود بالقارئ قبل تشغيل دفعة أكبر. نجاح توليد PDF أو الإرسال لا يُعد تأكيدًا ميكانيكيًا لخروج الورق.

## تحديث تجربة إدارة القوالب والمحرر

- «بيانات القالب» من بطاقة القالب أو عنوان المحرر يتيح تعديل الاسم والوصف وتعيين الافتراضي دون مراجعة تصميم جديدة. الحفظ ذري ويستخدم lock_version؛ تعارض البيانات يحتفظ بالمدخلات.
- المسودة ترسل التصميم فقط؛ تعديل بيانات القالب في تبويب آخر يؤدي إلى تعارض آمن بدل إعادة اسم قديم تلقائيًا.
- إنشاء القالب يطلب الاسم والمقاس والتصميم الابتدائي. يمكن حفظ ملصق فارغ كمسودة، لكنه لا يُنشر أو يُطبع قبل إضافة المحتوى. النسخ يطلب اسمًا ويترك قرار فتح المحرر للمستخدم.
- المحرر يستخدم مساحة مستقلة مع لوحات قابلة للطي وملاءمة تلقائية. إعداد الملصق والورق يستخدم نسخة مؤقتة، وتطبيقه خطوة تراجع واحدة. إلغاء النافذة لا يحفظ التغييرات.
- بيانات المعاينة وسجل النسخ وملاحظات الجودة في نوافذ مستقلة. قائمة «عرض» تتحكم في أدوات المساعدة غير المطبوعة.
- التلميحات تظهر بالماوس ولوحة المفاتيح، ودليل الأدوات قابل للبحث ومتاح من زر المساعدة وداخل إعدادات الملصق.
- API الجديد: PATCH /api/v1/label-templates/{id}/metadata؛ الحقول name وdescription اختيارية، make_default=true يحتاج صلاحية الافتراضي وقالبًا منشورًا. lock_version مطلوب، وcompany_id ممنوع.

ترحيل الباك إند الجديد (شُغّل على التطوير المحلي فقط):

```sh
php artisan migrate --path=database/migrations/2026_10_28_150000_add_label_template_description.php --force
```

إعدادات P2 ومحرك الرسم لم يتغيرا؛ فحوص الواجهة تمنع أي اتصال بالخدمة المحلية للطباعة.
## الصفوف المرنة وتنسيق الأسعار (وصف التصميم 2)

أداة «صف مرن» تجمع عناصر مستقلة، أو حدد عنصرين ثم «وضع داخل صف». يمكن إرفاق العناصر من خصائص الصف أو اختيار «الصف الحاوي» في خصائص العنصر. اسحب الطفل لإعادة ترتيبه أو استخدم «قبل/بعد». لا تدعم المرحلة الأولى الصفوف المتداخلة أو دوران الصف. حذف الصف يحذف عناصره؛ «فك الصف» يبقيها في مواضع المعاينة الحالية.

التوزيع الافتراضي حسب المحتوى، مع أعمدة متساوية أو نسب مخصصة. الالتفاف اختياري وداخل ارتفاع الصف فقط. الحساب يبدأ بعد تنسيق القيم وتحميل الخطوط. لا تحفظ مواضع الأبناء المحسوبة أو بيانات الاختبار في المراجعة.

حقول السعر الجديدة لها إعداد priceFormat: decimals من 0 إلى 6، trimZeros، showCurrency، currencySymbol، currencyPosition وgroupThousands. التقريب عشري والنصف بعيد عن الصفر؛ لا تغيير للقيمة الأصلية. تؤخذ العملة من settings.currency_symbol أو settings.currency في الشركة؛ إذا غابت يمكن تعيين الرمز في العنصر أو تعطيل العملة. التحويل الصريح للسعر القديم يزيل العملة المصرية الثابتة ويحفظ رمزها كتفضيل للعنصر. لا تتحول القوالب القديمة تلقائيًا.

«بيانات المعاينة» تتضمن اختبار قيم مؤقتة مع أمثلة للكسور والأرقام الكبيرة والحقول الناقصة. ملاحظات التداخل تحدد العناصر وتوفر التحويل إلى صف ومساواة العرض واعتماد التداخل المقصود. الاعتماد مرتبط بوصف العنصرين ومواضعهما المحسوبة ويحتاج إعادة المراجعة عند تغيّرهما.

المحرك يفحص جميع السجلات قبل إرسال PDF أو فتح الطباعة. أي حقل مطلوب ناقص أو سعر لا يتسع أو رمز غير صالح أو تداخل غير معتمد يمنع الدفعة كاملة. تصغير الخط ضمن الحد الأدنى ملاحظة وليست أمر إعادة طباعة. بروتوكول P2 لم يتغير.

تحقق إضافي دون طباعة فعلية:

```sh
node tools/label-templates/verify-flex.mjs
```

لا توجد هجرة قاعدة بيانات لهذا التحديث؛ البنية الجديدة محفوظة داخل JSON. يجب نشر الباك إند الداعم للإصدار 2 قبل الفرونت، مع إعادة تحميل تبويبات المحرر القديمة قبل تعديل مسودات الإصدار الجديد. مراجعات الإصدار 1 تبقى كما هي.
